# 档案室 · 第四轮方案（2026-10-08）

> **状态（2026-10-12 搬进仓库时注）**：已做完（#62）。
>
> 原件在 claude.ai 项目文件夹 `ideas/霏微-档案室第四轮方案.md`，以后只改仓库里这份。

YosH 看了第三轮合并后的效果，提了三件事：

1. 坐下来读时，灯和文件不像在一个层面上。
2. 没有阴影，也没有明暗过渡。
3. 并排对照时更奇怪，而且过曝。

## 原因（查代码得出）

**纸不在桌上。** 读档的纸是 DOM 里一张平的卡片（约 705 × 712 像素），正对屏幕盖在 3D 画面上。桌上那张真的 3D 纸被它盖住了，只在并排时从中间露出一小块。灯、桌子、椅子有透视，纸没有，大小也不成比例：纸比整张桌子上的东西都大。所以灯和纸看起来是两个世界的东西。

**纸上的光是假的。** 纸上的明暗是一层 CSS 渐变，只用到灯的方向和总亮度，没有阴影，没有边缘厚度，也没有纸压在吸墨垫上的接触影。

**3D 里几乎没有阴影。** 桌上的验档灯 `castShadow = false`，灯头、档案夹、纸在桌面上都没有投影，明暗过渡只有聚光灯的锥形边缘。

**并排过曝。** 渲染器是 `NoToneMapping`，亮度超过 1 就直接截成白。夜里验档灯强度约 10，灯头离桌面只有 0.3 米左右，按距离衰减算出来的亮度是白色的好几倍。再叠上灯管的发光、加色混合的光晕、两盏台灯，中间那块桌面就整片是白的。右边的第二张纸（`companion`）也是一张平的 DOM 卡片，和桌上的东西没有关系。

## 改法

### ① 先把亮度和阴影做对（3D 部分）

- 渲染器换成有肩部的色调映射（ACES），读档时再按距离压一压曝光，亮的地方过渡到白而不是直接截断。
- 验档灯的亮度按它离纸的距离换算，而不是固定值，保证纸面亮度和密级对得上：密级越高越亮，但不过曝。光晕改成薄薄一圈，只在从侧面看灯管时才明显。
- 桌上的灯（验档灯和两盏黄铜台灯）开阴影：灯头在桌上投影，档案夹和纸在吸墨垫上投下软影，另外在每份档案夹、每张纸下面铺一层很淡的接触影。
- 光斑要有一个亮的中心和暗下去的边：灯下最亮，吸墨垫边缘、桌边渐渐暗下去，而不是整张桌子一样亮。

### ② 纸真的躺在桌上（最关键）

- 每帧用 3D 里那张纸的四个角投到屏幕上的位置，算出一个变换，把 DOM 的纸贴到上面。纸就有了和桌子一样的透视：远边略窄，近边略宽，边缘和桌上的档案夹对齐。
- 字还是真正的网页文字，能选、能搜、能滚动，不用把页面画成图片。倾斜角度压在读字不吃力的范围内（俯身看，近似正对）。
- 纸的光从 3D 里算：明暗渐变按灯的位置和光锥来，灯头挡着光的地方有一条软影，纸的边缘有一圈很细的厚度和接触影。
- 纸的大小和 3D 的纸一致。现在的做法让纸大到像一块海报，改完以后纸是桌上那张纸，镜头靠近它。

### ③ 并排对照真的并排

- 第二份档案的纸摆在右边的吸墨垫上，和左边那张一起被同一批灯照亮，两张纸都贴在桌面上。
- 镜头拉开一点，让两张纸、中间的验档灯都在画面里。并排时每张纸比单独读时窄，想读哪份就点「换到前面读」，换过来就是单独读的大小。

### ④ 手机

手机竖屏放不下整张桌子，继续用现在的平纸，但纸上的光和阴影换成同一套算法，不做桌面透视。

## 要你定的一件事

纸的比例：

- **放大到约 1.3 倍**（推荐）：档案夹和纸都比真实的 A4 略大，像一份大开本的案卷。灯头、纸、桌面能同时在画面里，字也够大。
- **严格按真实 A4**：最真实，但字要么很小，要么灯不在画面里，两样只能保一样。
