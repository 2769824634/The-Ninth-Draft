# 协作：两个 Claude 账号和 Codex

作者 YosH 有两个 Claude 账号，以后可能再加 Codex，都在这一个仓库里干活。这份讲谁能看到什么、怎么分工、怎么不撞车。2026-10-12 写。

| 谁 | 在哪干活 | 看得到 | 看不到 |
| --- | --- | --- | --- |
| **作者 YosH** | 手机和 Windows 笔记本 | 全部 | — |

所以：**所有人共享的只有这个仓库。** 凡是别人需要知道的（做到哪、定了什么、哪里没做完），都要写进仓库：合并的 PR 写进 `docs/进度.md`，作者新定的规矩写进 `CLAUDE.md` 或 `docs/作者的规矩.md`，设定写进 `docs/设定/`，没做完的事写在 PR 描述里。只在对话里说过的话，另一个账号永远看不到。

## 核心编辑：账号一（2026-10-12 作者定）

作者原话：「你是核心编辑，来定大方向和开发重点，千万不要被干扰，尤其是main」。所以：

- **账号一定大方向和开发重点。** 做什么、先做什么、`docs/进度.md` 里「接下来的次序」，由账号一和作者商量后定。账号二和 Codex 不自己开新方向，只接作者或账号一交给它们的活。
- **只有账号一把 PR 合进 `main`**，而且照旧要作者先说「合并」。账号二和 Codex 只开 PR，不合并；它们的 PR 由账号一审过（对照 `CLAUDE.md`），再请作者定。
- **`CLAUDE.md` 和 `AGENTS.md` 只由账号一改**（作者点头后）。账号二想改设定或规矩，写进 `docs/设定/设定补充.md` 或在 PR 描述里提，由账号一并入。
- **`main` 有保护**：只能通过 PR 改，PR 上的「规矩检查」和「构建」都通过才能合并，不能强推、不能删分支。注意两个 Claude 账号在 GitHub 上用的是作者同一个 GitHub 身份，GitHub 分不出是哪个账号，所以「只有账号一合并」这条靠大家守规矩，不靠 GitHub 拦。

## 以什么为准

1. 作者最新说的话。
2. 账号一（核心编辑）对方向和先后的安排。
3. `CLAUDE.md`：设计决定的总账。
4. `docs/作者的规矩.md`：工作规矩和习惯。
5. `docs/设定/`：设定资料，每份开头标了现行、参考还是过时。
6. 其他。

作者在对话里定了新规矩，听到的那个账号负责把它写进仓库（小改可以放进手上正在做的 PR，并在 PR 描述里写明「作者 某月某日 定」）。

## 开工前（每次）

1. 拉最新的 `main`。
2. 读 `CLAUDE.md`、`docs/作者的规矩.md`，再看 `docs/进度.md` 的「现在」一节。
3. 看 GitHub 上**打开着的 PR**：那是实时的占位表，比 `docs/进度.md` 新。谁的 PR 在改你要改的文件，就先别碰，或者先问作者。
4. 不确定要不要做、做成什么样：先问作者，给两三个选项、标推荐。

## 干活时

- **一件事一个分支、一个 PR**，从最新 `main` 开分支，**永远不直接推 `main`**（推到 `main` 会立刻部署上线）。
- 开工就尽早开 PR（可以先开草稿 PR），标题写清做什么，这样另一个账号马上能看到你在改哪。同时在 PR 里把 `docs/进度.md` 占位表加一行。
- PR 描述用中文，先写「之前：」「之后：」两段（读者看到什么），再一小段「怎么做的」。描述第一行之后写一行「来自：账号一 / 账号二 / Codex」。
- 改了看得见的东西，附截图：电脑一张、手机竖屏一张，中英文都动了就各一张。作者在手机上看，截图集做成网页发链接（见 `docs/作者的规矩.md`）。
- 推之前跑 `npm run build` 和 `node scripts/check-rules.mjs`。
- 作者说「合并」才合并，由账号一合（见「核心编辑」）。合并前在 PR 里把 `docs/进度.md`「合并记录」的那一行加好、删掉占位表那一行。
- 合并后另一个账号手上的 PR 如果冲突了，由那个 PR 的主人把 `main` 合进去解决，不改写别人分支的历史。

## 分工

**原则：同一块地方同一时间只有一个人改。** 「一块」指一间房（档案室、资料室、办公室）、地图、登记流程、日报、`CLAUDE.md` 这类单位。

现在（2026-10-12）账号一占着的地方见 `docs/进度.md` 占位表：档案室（例行文件柜、吊灯、卡顿排查）、资料室和日报（#88）、`CLAUDE.md` 的内容（#88），以及本目录。

账号二的默认做法：只做作者或账号一交给它的事，从占位表以外的地方做起，开工前跟作者说一声。可以交给账号二的候选（都不碰账号一占着的地方，由账号一和作者决定给不给）：

- 日报读者来信署上邻居的名字（居民登记留下的小事；日报在 #88 合并后才空出来）。
- 地图上巴刹、小贩中心纸条里写摊主。
- 朋友写稿的入口和格式（`docs/设定/写稿须知.md` 等作者审过之后）。
- 内容：作者出题后写支线初稿、例行表格的文字题库（和账号一对好接口再做）。

**`CLAUDE.md`**：只由账号一改，改之前要作者点头，一次只有一个 PR 改它。现在 #88 正在改。

### 自动检查查什么

规则在 `scripts/rules.json`，脚本 `scripts/check-rules.mjs`。只看这个 PR **新加的行**，老代码不算。

| 检查 | 结果 | 说明 |
| --- | --- | --- |
| 网站能构建 | 失败就拦 | `npm run build` |
| 受保护的文件 | `codex/` 分支改了就拦 | `CLAUDE.md`、`AGENTS.md`、`.github/`、`.cursor/`、检查脚本和规则、`astro.config.mjs`、`package.json`、`package-lock.json`、`.claude/` |
| 新的图片、音频、模型、字体 | `codex/` 分支加了就拦；其他分支加音频会提醒「确认不是商用歌曲」 | 素材只能原创，Codex 不加素材 |
| 外部网址 | 拦 | 代码和数据里新出现的 `http(s)://` 网址，除了允许列表（求助热线、地图出处、SVG 命名空间等）。防止引入外部图片、字体、脚本 |
| 暗设定词 | 提醒 | 界面和数据里新出现「第九稿」「The Ninth Draft」「前几稿」等。档案里的 Heuss 批注可以有，所以只提醒不拦 |
| 「稿」当时间用 | 提醒 | 「慢一稿」「三稿以前」「drafts ago」这类 |
| 中英没一起改 | 提醒 | 改了 `xxx.json` 没改 `xxx.zh.json`、改了档案 `.md` 没改 `.zh.md`，或反过来 |

「提醒」会显示在 PR 的检查结果里，不挡合并，审的人看一眼判断。
